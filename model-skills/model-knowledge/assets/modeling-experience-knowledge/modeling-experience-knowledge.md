# 建模经验知识库

沉淀建模过程中的方法论、调参经验与踩坑记录，供 task-spec / tuning 阶段检索参考。每次建模完成后按模板追加条目。

## 分类组织

经验按任务类型分三类，编号前缀区分：

| 类别 | 文件 | 编号前缀 | 说明 |
|---|---|---|---|
| 通用 | 本文件（下方「通用经验条目」） | `EXP-G` | 跨任务类型通用的方法论 |
| 分类模型 | `classification-experience.md` | `EXP-C` | 二分类/多分类建模专属经验 |
| Uplift 模型 | `uplift-experience.md` | `EXP-U` | 增益建模（S/T-learner 等）专属经验 |

检索时先判断新任务类型：分类任务读 通用 + `classification-experience.md`；uplift 任务读 通用 + `uplift-experience.md`。

## 条目模板

```markdown
### {前缀}-{三位序号}｜{一句话标题}
- 日期：yyyy-mm-dd
- 任务类型：{通用 / 分类 / uplift}｜业务域：{用户运营 / 增长 / ...}
- 关联模型：{model_id，可空}｜关联 session：{runs/ 目录名，可空}
- 背景：当时要解决什么问题
- 做法：采取的方案（特征 / 算法 / 参数 / 样本处理）
- 结论：效果如何（关键指标前后对比）
- 教训/建议：下次同类任务的注意事项
```

归档时按类别追加到对应文件，并在该文件的索引表中登记。

## 通用经验条目

### EXP-G-001｜样本时间窗与 OOT 切分
- 日期：2026-07-04
- 任务类型：通用｜业务域：通用（种子条目）
- 关联模型：—｜关联 session：—
- 背景：训练/评估切分不当会导致线上效果与离线评估脱节。
- 做法：train/test 按时间窗内随机切分，OOT 单独留出最近一段完整时间窗（如最近一个月），不与训练窗重叠。
- 结论：OOT 上的指标更能代表上线后表现；以 OOT 指标作为模型选型的主要依据。
- 教训/建议：正样本稀疏时优先拉长训练时间窗而不是过度下采样负样本；报告中必须写清 `train：~｜oot：~` 时间窗。

### EXP-G-002｜高 PSI 特征处理
- 日期：2026-07-04
- 任务类型：通用｜业务域：通用（种子条目）
- 关联模型：—｜关联 session：—
- 背景：部分特征在 train 与 OOT 之间分布漂移大，模型分随时间不稳定。
- 做法：feature-analysis 阶段计算特征 PSI，PSI > 0.1 的特征标注 `[PSI_WARN]`；重要性高且 PSI 高的特征做剔除前后对比实验。
- 结论：剔除高 PSI 特征通常小幅牺牲 train 指标，换取 OOT 稳定性提升。
- 教训/建议：不要只看单点指标决定去留，结合模型分 PSI 与分档单调性判断；报告中保留剔除清单。
